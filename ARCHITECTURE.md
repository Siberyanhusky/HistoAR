# HistoAR - Architecture Brief

> Onboarding + mental-model reference for anyone (human or agent) working on this repo.
> Read this before making changes. Snapshot: 2026-08-08, branch `ai/eng-review-t1-t12`.

## 1. What it is

Educational **WebAR platform for Indonesian prehistory** (Sejarah Indonesia SMA Kelas X), built with Prof. Wawan. A full port of the original vanilla HTML/JS **HistoAR** into React+TS, reusing the **HistoAR-Futuristik** design (aurora/glass, dark "future museum" theme). **All content is real** - pulled verbatim from the original `data/*.json`. No dummy content.

Learning flow: **Landing → Materi list → AR scan (explore all hotspots) → Quiz → HistoAI chat → unlock next materi**. UI copy is **Bahasa Indonesia**.

## 5. Two things that look duplicated but AREN'T

**A. Two AI chat paths - different context, both via Kie.ai:**
1. `lib/histo-ai.ts` → `askHistoAI` (TanStack **server fn**). Used by **landing** `sections/ai-guide.tsx`. Two-step: a **classifier** (RELATED/UNRELATED) gates to prehistory topics, then a strict system prompt. Refuses off-topic hard.
2. `routes/api/chat.ts` → `/api/chat` **HTTP route**. Used by post-quiz **`Chatbot.tsx`**. Prompt built from the specific materi's `judul` + `ringkasan`; softer (allows greetings + related general history). Body: `{ materi_id, pertanyaan }`.

**B. Two 3D paths - different engines, different jobs:**
1. **Marker AR** (`lib/ar-engine.ts` + `ArScan.tsx`): A-Frame + MindAR, imperative DOM. Real camera WebAR on materi pages.
2. **Showcase viewer** (`viewer/ViewerCanvas.tsx` + `MeganthropusViewer`): react-three-fiber/drei OrbitControls, no camera/AR. Landing `ar-showcase.tsx` only.

Do not "unify" these without a deliberate decision - they exist for distinct reasons.

## 6. `ArEngine` - the hard part

Imperative class ported from `ar-controller.js`. React only manages its lifecycle: `ArScan` mounts it in `useEffect`, wires callbacks (`onGateUpdate`, `onModelError`), calls `dispose()` on unmount. UI↔engine sync uses a **MutationObserver on `hidden`** attributes (engine toggles DOM by id; React mirrors into state). Shared DOM ids (`arSceneRoot`, `arPanel`, `arScanHint`, `arReopenBtn`, `arViewControls`, `arMoveControls`, …) **are the contract - renaming one breaks the other side.**

Non-obvious fixes already baked in (preserve - each has an explanatory comment):
- **Per-instance visited/opened state** (`Set`s on the instance), NOT on the imported `ar.json` object (module-level → leaks across AR sessions in the same tab).
- **`updateWorldMatrix` intercept**: always forward the update, **including the null matrix** - MindAR itself emits `targetFound`/`targetLost` inside it, so swallowing null (an older "keep last pose" attempt) killed `targetLost` and left models stuck on screen. Never force `object3D.visible = true` here (permanently kills `targetFound`).
- **`centerModelPivot()` measures in LOCAL space, never world space.** The anchor is init'd `matrixAutoUpdate = false` with a **zero** matrix until the target is first scanned, and GLBs finish loading long before that. World-space measuring → `Matrix4.invert()` of a zero matrix → `applyMatrix4` divides by `w = 0` → **NaN position → model never renders, ever.**
- **`ensureCameraFitPatch()` overrides MindAR's `_startVideo` + `_resize`** (prototype-level, so it's timing-independent): request a camera stream matching the screen orientation, and fit the preview **contain** instead of cover - stock MindAR pushed ~65% of the camera frame off-screen on a portrait phone.
- **Model sizing is normalized, not hand-tuned.** `normalizeModel()` measures each GLB's bounding box on load and maps its longest side to 1 wrapper unit. Since MindAR's `postMatrix` scales the anchor by the marker width, `zoom` in `ar.json` means **multiples of marker width** (0.85 = fits with margin). The old `scale` field is gone. Measure with `geometry.boundingBox` only - `SkinnedMesh.boundingBox` is in **skeleton space** and chaining it with `node.matrix` mixes frames (measured 4.63x error on `meganthropus.glb`).
- **`focus` = per-hotspot camera target**, a point in model space as a fraction of model size. Wrapper position is `-rotY(focus x zoom)`, so the focused point stays locked at the marker centre through zoom and rotation - this is what makes "switch hotspot = move viewport" feel like a camera dolly rather than the model inflating. Calibrate live with `?dev=1` + D-pad + the ruler button (it copies `focus` too).
- **Scene attribute is `xr-mode-ui`, not `vr-mode-ui`** - A-Frame 1.5.0 renamed it, and unknown attributes fail silently, so the old name let the "Enter VR" button through.
- **`dispose()`** stops MindAR system + all `<video>` tracks (camera leak), removes A-Frame's `a-fullscreen` class from `<html>` (else other pages can't scroll), clears timeouts/listeners.
- `load-script.ts` waits for existing in-flight `<script>` load (StrictMode double-invoke → "a[e] is not a constructor" race).
- Dev helper: **copy-view** button writes `defaultView`/`view` JSON snippets to clipboard for pasting into `ar.json`.

## 7. Data model

`histoar-types.ts` mirrors the JSON. ~17 materi ids: `m1`, `m2-1..m2-6` (incl. `m2-4-1..6`), `m3-1..m3-5`.
- **`materi.json`** → `Materi[]` (`id, urutan, kode, layerColor, judul, ringkasan, konten[]`).
- **`quiz.json`** → `Record<materiId, QuizQuestion[]>` (`pertanyaan, opsi[], jawaban` index).
- **`ar.json`** → `Record<materiId, ArMateriConfig>` (`targetMind, maxZoom, targets[]`; each target: `targetIndex, model, hotspots[]`, optional `defaultView`, `introAudio`). Not every materi has an AR config.

**Progress** (`progress.ts`, localStorage `histoar_progress = {completed[], scores{}}`): completing = finish quiz + chat once. NOTE: `isMateriUnlocked()` currently **hard-returns `true`** (per-urutan lock intentionally disabled for now).

## 8. Design system

Tailwind v4, **dark-only** "future museum". Tokens in `styles.css` via `@theme` + `:root` (oklch). Signature: `--holo` gradient, `--aurora-*`, glass utilities (`glass`, `glass-strong`), `shadow-holo`. Fonts: Space Grotesk (display), Inter (sans), JetBrains Mono (mono). shadcn base color slate, lucide icons.

## 9. Build / deploy / workflow

- `npm run dev` → Vite dev on **:3000**. `npm run build` runs `check:vendor` (sha256 gate) then `vite build`. `lint`, `format` available.
- Deploy **Vercel** (Nitro vercel preset; `.vercel/` present). Env: **`KIE_AI_API_KEY`** required for both AI paths.
- Error handling layered: `start.ts` middleware + `server.ts` h3-500 normalizer → branded error page.

## 10. Known rough edges (not yet addressed)

- Two lockfiles (bun + npm) - pick one to avoid drift.
- `isMateriUnlocked` always returns `true` - sequential locking is off.
- `ViewerCanvas.tsx` has leftover `console.log`s and an empty `useFrame`.
- `ArScan`'s `onAllExplored`/engine `onQuizReady` is a no-op (gate enforced via button `gateReady` instead).
